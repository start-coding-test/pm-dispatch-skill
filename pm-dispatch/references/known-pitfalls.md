# 本机已知坑库

写卡片第 6 节时按条挑用，**只抄与这张卡相关的**，不要整篇灌进去。
每条都来自本机实际踩坑；涉及关键路径时下发前重新实测一条，坑会变。

## Shell 与路径

- **只认 pwsh7 与 Git Bash**。不要为 cmd.exe / `.bat` / PowerShell 5.1 写兼容代码，BOM、`chcp`、TLS 补丁都是假问题。
- **给执行 agent 的命令必须绝对路径**。相对路径在 Git Bash 和 Windows 原生程序之间语义不一致，弱模型会走错目录。
- 反斜杠路径放进带引号的命令里最稳：`node "D:\proj\scripts\run.cjs"`。
- Git Bash 会把 `$_`、`$p` 这类 PowerShell 变量在传给 `powershell -Command "…"` 前先吃掉，
  导致命令变形。要么把 PS 脚本写成 `.ps1` 用 `-File` 跑，要么用单引号包裹整个 PS 命令。
- 给 Windows 原生工具传 `/FI`、`/IM` 这类开关时 Git Bash 会把它当路径转换；改用 `MSYS_NO_PATHCONV=1` 或换写法。

## Node

- Windows 上 `child_process.spawn` 配 `shell:false` **无法启动 PATH 上的 `.cmd` shim**（`ENOENT`），也**无法直接 spawn `.cjs`/`.js`**（`EFTYPE`）。必须写成 `node` + 脚本绝对路径，例如 `node "D:\proj\scripts\run.cjs"`。
- 没有 `package.json` 的目录里写脚本用 `.cjs` 扩展名，避免 ESM/CJS 判定分歧；反过来产物目录里跑 ESM 就用 `.mjs`（`.js` 会被判成 CommonJS，`import` 直接报错）。
- 常驻单测要用 `new URL("相对路径", import.meta.url)` 解析被测源码，**不要写死绝对 file URL**——
  否则卡片产物一旦收拢进仓库就换一台机器/目录就失效。
- `find` 从 `.` 或具体目录起步，不要从 `/` 起步扫全盘。
- 语言服务器/构建工具的 PATH：某些工具链装在用户目录下而新 shell 不含它（如 `~/.cargo/bin`），卡片要写明"每个新 shell 先加 PATH"。

## 权限与运行时验收（最容易让一卡白跑）

- **执行会话和 PM 会话都可能被权限分类器拦住"起 GUI 实例""读工作区外的配置"**。
  拦一次就换路径，**不要反复重试同一条命令**——重试既污染判定又耗光上下文。
- 需要提前约好分工：卡片给出起实例的**完整前置命令**（含环境变量、绝对路径），
  PM 侧被同一命令拦住时改成**用户起实例、PM 只跑套件**。
- 任何 PM 没能亲自复跑的验收项，写进台账「PM 未复跑」一节，**不混进 PASS 依据**。
- 工作区外的文件读取可能被直接拒（例如用户级应用的配置文件）。取证卡若必须读它，
  改为"卡片内贴原始输出 + PM 用代码侧交叉核对替代"，并在验收里明说这一项没复现。

## 进程

- **禁止 `pkill -f` / `taskkill /IM`**。按映像名或命令行模糊杀会连带杀掉 IDE 自己的进程。
  只允许停自己启动的进程：记下 PID，用 `Get-Process -Id 12345`（换成实际 PID）核对 ExecutablePath 后再停。
- **停止一个包装命令不等于停止它的子进程**。`npm run dev` 这类被中断后，
  子进程（dev server、应用本体、语言服务）常留在端口上活得好好的，症状是下一次启动报
  `Port … is already in use`，看起来像端口冲突其实是自己留的孤儿。
  收尾三查：端口（`netstat -ano | grep :5173`）、映像名（`tasklist | grep -i myapp`）、
  归属（`Get-CimInstance Win32_Process -Filter "ProcessId=12345"` 取 CommandLine）后再按 PID 精确停。
  （端口、映像名、PID 都换成实际值——抄进卡片前先换，门禁会拦尖括号槽位。）
- **禁止在卡片里要求启动 GUI**：全屏置顶窗口配合外层 `timeout` 会耗尽会话 desktop heap，
  导致新窗口开不出、Ctrl+Alt+Del 无响应，只能强制断电。必须由脚本自己收窗、自己判父进程存活。
- 卡片要写死"任务结束时必须关掉自己启动的进程 + 确认端口已释放"。

## 断言与判据（返工的头号来源）

- **卡片措辞必须是做得到的**。写每条验收判据前自问"物理上能成立吗"。真发生过的不可实现要求：
  文案长度上限超出容器容量；"改写别人配置文件后他人条目**逐字节**未变"（序列化库会整文件重排键序，
  要保住键序得加新依赖）；"首次调用该能力时弹同意框"（宿主在激活时就把缺失能力一次性弹完了）。
- **别把外部依赖的可用性写进断言**。"某域名必坏""某数据源一定返回 X"是环境属性不是代码属性，
  环境一漂整批常红。要做的是状态无关判据（"有值才比大小，无值必无量"）+ 判定输入现场打印。
- **别把时段/交易状态写死**。盘前、竞价、收盘后同一份数据的形态不同，盘口为空时
  `a[0] <= price <= b[0]` 这种比较必假。
- **DOM 选择器要对着实现选**：有的框架助手函数第三参赋的是 `className` 不是 `id`，
  用 `getElementById` 查它永远为 null。写断言前先看元素是怎么造出来的。
- **不许用固定 `sleep` 赌异步渲染**。等状态一律 `waitUntil`；缺元素要产出可读 FAIL，
  不要 `document.getElementById(x).click()` 直接点——一个 TypeError 能把整个套件打断，
  尾部汇总和后面几十条断言一起丢失。
- **静态断言条数 ≠ 运行时断言条数**（循环里同一条标题会跑多次）。下限写运行数，核对用标题集。
- 断言只许变严不许变松；打回时要防两种省事路径：把上限调大凑绿、把判据整条删掉。

## 取证卡的产出怎么写才可用

- 每张取证卡的最后要求一行机器可判定的 `RESULT k=v …`（条数、发现数、改动文件数），PM 用它做机械判定。
- 报告里每条结论都必须带 `文件:行号` + 原文引用，PM 会随机抽 ≥5 条打开对原文。
- 无法从仓库内取证得出的结论必须标 `[推测]`；被拦在外部的读取要写成"未复现"。
- **报告优先于卡片的背景陈述**。卡片正文里的"已实测事实"可能已经过时（行号漂、结构变、事实被后续改动推翻），
  取证卡回传后要以报告为准，并回改卡片/规格文档里那条过时事实。

## 同工作树多卡并行的纪律

- 产物有 `work/Txx/` 隔离，**源码改动没有**。同批两卡碰同一文件 → 必然互相覆盖，排批时按互斥处理。
- 多卡在同一工作树串行执行后，`git diff --name-only` 是**混合的**。验收按各卡白名单的**并集**核对，
  并在结果文件里请对方标注"哪些是我的"。PM 统合时分包提交。
- **禁止回滚工作树里不属于本卡的改动**：`git checkout -- 某文件`、删文件、"先还原到干净状态"
  都会直接毁掉另一张卡未提交的工作。看到白名单外的改动只读不动，并在结果里报告。
- 未跟踪的新文件（刚创建的脚本/产物）**不能靠 `git checkout` 还原**——git 里没有它，会直接丢。
  变异/试改一律在 `temp/` 副本上做，还原后**逐字节校验**。

## 基线与行号会漂

- 一批改动插进几十条断言后，后续卡片引用的 `文件:行号` 会整体后移。**每批放行后立刻重核下一批卡的锚点**。
- 验收证据矩阵（哪类改动跑哪套 + 上一轮实测运行数下限）要随批更新，并在矩阵里标注"该基线暂不可用"的情形。

## Git

- 执行 agent 一律只读 git（`status` / `log` / `blame` / `diff`）。`commit` / `push` / `checkout` / `reset` / `clean` / `stash` 全部禁止——统合与提交由 PM 在验收后做。
- 共享工作区里禁用裸 `git stash`，会连带影响其他人的工作。
- 被打回卡的改动留在工作树不提交；未放行能力的文档也不要提交（文档跑到代码前面会误导下一个人）。

## 目录卫生

- 临时文件只进项目根下的 `temp\`（卡片里写成绝对路径），用完删除；打包产物进项目约定的产物目录，**不要用构建输出目录当产物目录**
  （`dist/` 这类会被下一次 build 清空，本项目因此丢过两次成品包）。
- 一卡一 `work\Txx\` 目录，产物绝不落到共享目录——这是并行不冲突的前提。
- 需要执行 agent 建目录时，卡片里先让它在写之前 `ls` 确认父目录存在。

## 无头执行器 / 子代理

- 无头 CLI 默认权限往往比交互会话更紧或更松，两者都危险：PM 先拿一张 T 卡试跑，确认它**只写了白名单**再批量用。
- 子代理和主会话共享工作树：白名单重叠的卡绝不同时派，调度器会挡，但 PM 手动派时要自己守住。
- 执行器退出码 0 只说明进程跑完，不说明结果文件存在、更不说明通过。`dispatch.cjs run` 会同时检查结果文件。
- 执行器卡死时 `--timeout` 到点会杀掉它；卡片仍要写"结束前关掉自己起的进程"，超时杀不到孙进程。
- 重派前旧结果文件必须挪走（`dispatch.cjs` 自动改名 `.retryN`），否则会把上一轮结果当成这一轮的。

## 弱模型行为特征

- **槽位写法会被原样照抄进命令**：尖括号包裹的 owner／路径／任务号、双花括号槽位、`（待填）`。卡片里一律写实值；确实要举例时同行注明「以 T06 为例，换成你自己的任务号」。
- 静态门禁会抓代码里的泛型/格式串（`<HTMLDivElement>`、`"<exe> --flag <phase>"`）。**别往白名单加词**，
  把正文改写成不含尖括号的描述——既过门禁，又不让对方照抄。
- 它们**确实会诚实报 PARTIAL**（例如"某套件被权限拦住没跑"）。这是好事：契约里要写明
  "严禁把未验证写成已完成"，并对诚实的 PARTIAL 给出处置（PM 补跑），否则下一批就开始猜。
- 它们会**反过来纠正 PM 的事实**，而且常常是对的（把"保守"纠正成"误报"、把注释与实现的不一致指出来、
  把 PM 写的错误时机指出来）。规矩：采纳前先复现，复现后回改到源头（卡片 + 规格 + 约定表）。
- 它们会自行发明公共工具（超时包装器、日志格式）。脚手架由 PM 先建好验证，卡片里给出绝对路径直接引用。
- 不确定的结论要求它们保留 `[推测]` 标注，否则推测会伪装成事实进入验收。
