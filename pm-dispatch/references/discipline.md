# 跨批次纪律

SKILL.md 只放每次都要走的流程；这里是"跑到第二批、第三批才会烂"的东西。排第二轮派发前翻一次。

## 1. 基线纪律

项目里维护一张**验收证据矩阵**（哪类改动必须跑哪套 + 上一轮实测的运行数下限），并遵守：

- **每放行一张卡就更新矩阵数字**，以及**后续卡片里引用的所有 `文件:行号`**——
  一张卡插进几十条断言，行号会整体后移，旧锚点会把执行者带到别的代码上。
  流水线派发下没有"批次边界"可等，所以这一步挂在"放行"动作上，而不是"批次结束"上。
- 下限数字只用来拦"倒退"，**不能反过来当目标**（把套件改绿就交 = 放宽回归）。
- 外部依赖的可用性**不是代码属性**：把"某个域名必坏""某个源一定返回 X"写进断言，
  环境一漂就整批常红。这种红在矩阵里标"该基线暂不可用"，不许拿它打回别人。

## 2. 权限现实

执行会话和 PM 会话都可能被权限分类器拦住"起 GUI 实例""读工作区外的配置"。这不是 bug，是流程约束，
必须提前和用户约好分工，否则验收会卡在半路：

- 卡片把需要的运行时环境写成**一条前置命令**（含环境变量与绝对路径），并注明"被拦就记 PARTIAL，不要反复重试"。
- PM 侧被同一命令拦住时，改成**用户起实例、PM 只跑套件**；跑完明确告知可以关。
- 任何 PM 没能亲自复跑的验收项，写进台账「PM 未复跑」一节，不混进 PASS 依据。

## 3. 执行者纠正 PM —— 这是常态，不是事故

实际发生过：卡片说"逐字节未变"（做不到）、说"首次调用弹框"（时机错）、说"某函数返回 10 只是保守"
（实为误报）、说"元素用 id"（实现赋的是 class）。处置规矩：

- 执行者在「需要 PM 决策」里给的**事实**，优先级高于卡片正文——他们手上有你没有的现场。
- 但**不采信任何未经 PM 复现的结论**：先重跑，再改文档/卡片/台账，最后回写"这条是谁发现的"。
- PM 自己写错的事实要**回改到源头**（卡片、规格文档、约定表）：同一条错误通常同时存在于三处。
- 同一个错误事实如果还躺在**尚未派出的卡**里，先改那些卡再派——流水线模式下这一步最容易漏。

## 4. 卡片粒度

- 执行者 15–45 分钟能做完是甜区。太碎：PM 写卡 + 验收的固定成本吃掉并行收益；太大：一次打回浪费一整卡。
- 一张卡里装着"两个依赖等级不同的活"就拆（`A9a` / `A9b`），别整体压在最后。
- 删入口的卡必须与替代入口同时或更晚放行——中间版本里功能会凭空消失。
