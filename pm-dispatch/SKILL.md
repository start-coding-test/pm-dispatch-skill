# 项目经理派发（PM Dispatch）

主会话是**项目经理**：只做拆分、写卡、调度、验收、统合。机械耗时的批量执行写成任务卡，交给 flash 档模型并行跑。
**判断留在主会话，执行外派出去。** 速度来自三件事：能并行的立刻并行、验收强度随风险走、打回一次就修对。

按需翻阅（不要凭记忆）：
- `references/acceptance.md` — 每次验收现场照做
- `references/discipline.md` — 第二轮派发前翻：基线/行号漂移、权限现实、执行者纠正 PM、卡片粒度
- `references/known-pitfalls.md` — 写卡 §6 时按条挑
- `assets/card-template.md` — 写卡模板
- `references/cloud-pm.md` — 可选：开了 Notion 云端 PM 时翻（写卡加三行、处理回复）

脚本都在本技能的 `scripts/` 下，零依赖，只要 Node。先定位技能根（不写死安装目录）：

```
S="$(ls -d "$HOME/.agents/skills/pm-dispatch" "$HOME/.qoder-cn/skills/pm-dispatch" "$HOME/.zcode/skills/pm-dispatch" "$HOME/.codex/skills/pm-dispatch" "$HOME/.claude/skills/pm-dispatch" .agents/skills/pm-dispatch .claude/skills/pm-dispatch 2>/dev/null | head -1)"
```

## 分诊：这张卡给谁

| 特征 | 归属 |
|------|------|
| 产出能独立验证；批量、重复、逐条套同一规则（补测试、加类型、迁移字段、逐文件改写、数据收集） | 外派 |
| 需要全局推理、跨多文件权衡；定义验收标准、选接缝、敲定术语、架构决策 | 自留 |
| 不可逆或碰共享状态（push、删数据、改 CI、装依赖、动 git）；发布/打包（S 卡） | 自留，且需用户明确开口 |
| 一句话能改完 | 自留（外派成本高于收益） |

**写卡前必问**：执行 agent 看不到这段对话，卡里缺的事实他能自己补吗？补不了就写进卡。

## 卡型

| 前缀 | 类型 | 并行性 |
|---|---|---|
| `T` | 取证 / 离线单测，只读或只写 `work/` | 最好并行 |
| `A` | 局部实现，改动面在一个模块内 | 白名单不重叠即可并行 |
| `B` | 跨模块实现，碰核心代码 + 回归 + 文档 | 通常串行 |
| `S` | 发布 / 工程 | PM 自留，调度器不会派 |

## 工作区

```
.dispatch/<功能名>/
├── ledger.md          台账，唯一进度事实源（只有 PM 写）
├── cards/T01-xxx.md    任务卡（只有 PM 写）
├── prompts/T01.txt     启动语（dispatch.cjs 生成）
├── results/T01.md      执行结果（只有对应执行者写；重派时旧的自动改名 .retryN）
└── work/T01/           该卡唯一可写的产物目录
```

产物天然无冲突；**源码改动没有这个保护**——两张卡白名单重叠就必须串行，调度器会自动挡住。

## 写卡：四条铁律

用 `assets/card-template.md`。卡头四个字段（卡型 / Blocked by / 独占资源 / 验收等级）是调度器的输入，§4 白名单决定能否并行。

1. **零占位符**：不许残留尖括号槽位、双花括号、`TODO`/待填、PM 注释。弱模型会原样照抄。示例写成"以 T06 为例，换成你自己的任务号"。
2. **命令实测**：卡里的命令 PM 先跑通再下发。公共脚手架（超时包装、日志格式、目录约定）由 PM 先建好，不留给 N 个执行者各自发明。
3. **判据做得到**：每条验收判据下发前自问"物理上能成立吗"。写不出可实现的判据 = 还没搞清这件事。（反例见 known-pitfalls「断言与判据」）
4. **禁反问**：卡里写明"不要向用户提问"，没覆盖的情况记 `BLOCKED` 后停止。

写完跑门禁，**0 error 才许派**：

```
node "$S/scripts/check-cards.cjs" "项目绝对路径/.dispatch/功能名/cards"
```

门禁同时做跨卡检查：依赖成环、引用不存在的卡、白名单重叠却无依赖关系。尖括号误报（代码泛型、格式串）一律改写正文，**别往白名单加词**。

## 派发：按依赖图流水线，不按批次一刀切

旧做法是"第 1 批全部放行才派第 2 批"，最慢的一张卡拖住所有人。现在由调度器按依赖图算：
**前置全部 PASS + 不与在跑的卡抢独占资源 + 白名单不重叠 + 并发未满** → 立刻可派，被依赖越多的卡越先派。

```
node "$S/scripts/dispatch.cjs" status "项目绝对路径/.dispatch/功能名"   # 谁能派、谁在等、为什么暂缓
node "$S/scripts/dispatch.cjs" next   "项目绝对路径/.dispatch/功能名"   # 生成启动语
```

派发方式只有一种：把 `next` 打印的启动语交给用户，**一张卡一个执行会话**（flash 模型）粘贴执行。
自动派发（子代理 / 无头 CLI）因各 harness 结构不同，暂不支持；不要自己用子代理工具或 CLI 顶替——它们常会继承主会话的大模型，或绕过白名单。

派出后把台账状态改成 `执行中`，然后**停下来等用户**回报，不要替执行者干活。
任何一张卡放行后，立刻再跑一次 `status`——新解锁的卡马上派，这是流水线提速的全部秘诀。

## 可选：云端 PM（Notion）

功能目录里有 `cloud-pm.json` 时，执行者卡住或做完可主动运行 `scripts/pm-ask.cjs` 呼叫 Notion 里的云端 PM，按回复继续，不必停下等用户。只做主动触发。云端 PM 跑不了命令，它的 `merge` 只算预审，**验收照旧由主会话重跑**；它拆出的新任务要改写成正式卡片过门禁再派。写卡要加的三行与指令页见 `references/cloud-pm.md`。

## 验收：强度随风险走（照 `references/acceptance.md` 做）

用户说「T03 跑完了」或执行器返回后，读 `results/T03.md`，按卡头的验收等级做：

| 等级 | 适用 | 必做 |
|---|---|---|
| **L1** | T 卡、只写 `work/` 的产物 | 存在性 + PM 重跑 §8 命令 + 引用抽查 ≥5 条 |
| **L2** | A 卡、补测试 | L1 + `audit-assertions.cjs`（回归没变松）+ `mutate-check.cjs` 抽 3 个点 |
| **L3** | B 卡、碰核心逻辑/回归脚本 | L2 + 变异 ≥6 点并用 `expect` 钉住具体断言 + 全套件 + 现场红同环境重跑两次 |

判定词：`PASS` 全中 ／ `PARTIAL（自报未跑）` PM 补跑，绿则 PASS（诚实的 PARTIAL 是好信号）／
`FAIL` 打回：PM 先改卡（§3 补事实、§10 写实测原样 + 根因 + 放行条件），再重派，不许原卡重发 ／
`BLOCKED` PM 的拆分缺陷，补卡再派。

验收列写**怎么验的**（重跑了什么、变异 RESULT 行、核对结论），不是只写 PASS。

## 统合

1. 把 `work/Txx/` 产物收拢到位，**改动后复跑**。
2. 跑全项目 typecheck + 测试套件。
3. **分包提交**：放行的卡各自一提交；打回卡的改动、描述未放行能力的文档，**留在工作树不提交**。
4. 两张卡产物指向同一目标文件 → 切片切错了，回 `to-tickets` 重切，别手工合并掩盖。
5. 调 `code-review` 收尾。push 需用户另行开口。

## 台账

`ledger.md` 是跨会话唯一事实源，每步动作后立即更新；新会话接手**先读 ledger 再读代码**。调度器读其中的表格：

```md
# 台账：登录功能
并发上限 3 | 门禁：6 张卡 0 error（2026-10-12）

| 卡 | 标题 | Blocked by | 状态 | 验收 |
|----|------|-----------|------|------|
| T01 | schema 单测 | 无 | 已回 | PASS（L1）：PM 重跑 243 条复现 → 提交 abc1234 |
| A02 | 字段迁移 | T01 | 执行中 | |
| B03 | 能力移交 | A02 | 打回 | FAIL：现场 4 红，根因见卡 §10 |

## 排批约束（本池实际生效的互斥）
## PM 已实测的前置事实（写卡依据）
## 状态流转记录（带日期，含 PM 自己改错的地方）
## PM 未复跑 / 待办项（不装作已验证）  ← 必须有
```

状态词：`待派` `执行中` `已回` `打回` `BLOCKED` `放行`。验收列以 `PASS` 开头即视为放行。
打回卡改完后把状态改回 `待派`，调度器才会再派。

## 卡片硬安全边界（§7 至少这些）

- 不读凭据文件（`.env`、`~/.ssh`、浏览器 profile、凭据管理器）
- 只读 git（`status`/`log`/`blame`/`diff`），不 commit/push/checkout/reset/clean/stash
- 不装/卸依赖，不改 lockfile
- 不按名字杀进程；只停自己启动的，按 PID + 可执行路径核对
- 不起 GUI/全屏置顶窗口（卡片明确要求的验收除外）
- 只写自己的 `work/Txx/` 与 `results/Txx.md`
- **不回滚工作树里不属于本卡的改动**——看到白名单外的改动只读不动并报告
- 做不到就如实记录并停，不把"做不到"写成"已完成"；不确定标 `[推测]`

## 工作流定位

```
grill-with-docs → to-spec → to-tickets ─┬─ 判断类 → implement → code-review
                                        └─ 机械耗时类 → pm-dispatch → code-review
```

与 `implement` 是并列的两条执行路线。同一批任务可以一半自留一半外派。
