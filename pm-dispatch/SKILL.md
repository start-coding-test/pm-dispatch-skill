# 项目经理派发（PM Dispatch）

主会话是**项目经理**：只做需求分析、拆分、写卡、调度、验收、统合。**不亲手做机械耗时的批量执行**——那部分写成任务卡，交给 flash 档模型在独立会话里并行跑，用户负责搬运。

判断留在主会话，执行外派出去。

**本文件的取舍**：流程与纪律写在这里；验收的具体操作手法（机械核对、变异抽查、打回卡怎么写）在
`references/acceptance.md`，每次验收现场翻那一份，不要凭记忆。

## 分诊表：先决定这张卡给谁

| 特征 | 归属 |
|------|------|
| 产出能独立验证，不需要对话里的隐性共识 | 外派（写卡） |
| 批量、重复、逐条套用同一规则（补测试、加类型、迁移字段、逐个文件改写、跑数据收集） | 外派（写卡） |
| 需要全局推理、跨多文件权衡 | 主会话自留 |
| 定义验收标准、选接缝、敲定术语、架构决策 | 主会话自留（走 to-spec / domain-modeling） |
| 不可逆或影响共享状态（push、删数据、改 CI、装依赖、动 git） | 主会话自留，且需用户明确开口 |
| 一句话能改完的小改动 | 主会话自留，外派成本高于收益 |
| 发布/打包/版本推进 | 主会话自留（S 卡），验收手段只有 PM 有上下文 |

**写卡前必问自己**：执行 agent 看不到这段对话，卡片里缺的事实他能自己补吗？补不了就必须写进卡片。

## 卡型（编号前缀就是调度信息）

| 前缀 | 类型 | 特征 |
|---|---|---|
| `T` | 取证 / 离线单测 | 只读或只写 `work/`，不起 GUI，**唯一能真并行的卡型** |
| `A` | 插件 / 局部实现 | 改动面局限在一个模块目录内 |
| `B` | 本体 / 跨模块实现 | 会同时碰核心代码、回归脚本、文档 |
| `S` | 发布 / 工程 | PM 自留，不派给执行模型 |
| `A9a`/`A9b` 式后缀 | 从属编号 | **一张卡里装着"两个不同依赖等级的活"时拆开**，别整体压在最后一批 |

## 工作区布局

在项目根的 `.dispatch/<功能名>/` 下：

```
.dispatch/登录功能/
├── ledger.md            PM 台账，唯一进度事实源（只有主会话写）
├── cards/T01-schema.md   任务卡（只有主会话写，执行 agent 禁改）
├── results/T01.md        执行结果（只有对应执行 agent 写）
└── work/T01/             该卡的产物目录（该卡唯一可写区）
```

一卡一目录一结果文件 → **产物天然无写冲突**。但**源码改动没有这个保护**：同批的两张实现卡如果改到同一份文件，
在同一个工作树里必然互相覆盖。所以互斥判断看第 2 节那套规则，不看"卡型是否相同"。

## 任务卡解剖

用 `assets/card-template.md`。十节缺一不可，其中三节最容易被写空：

- **§3 输入与事实**：只写**实测过**的值（绝对路径、真实版本号、真实行号）。写"约""应该是"就是让执行者猜。
- **§4 允许写入路径**：白名单 + 显式黑名单（"不许动 X，那是另一张卡的地盘"）。跨卡并行时这条是唯一护栏。
- **§8 自检与验收标准**：每条都必须是 PM 能亲自重跑的客观条件（命令 + 期望输出 + 退出码）。

### 四条铁律

- **零占位符**：交付出去的卡片里不许残留尖括号槽位、双花括号槽位、`TODO`。弱模型会原样照抄。示例值必须写成"以 T06 为例，换成你自己的任务号"。
- **命令实测**：卡片里的命令，主会话先自己跑通一遍再下发。公共脚手架（超时包装器、日志格式、目录约定）由主会话先建好验证，不留给 N 个 agent 各自发明。
- **判据必须做得到**：每条验收判据下发前自问一次"这条在物理上能成立吗"。反面实例（都是真的发生过）：
  要求常驻文案 ≤60 字却不超出容器容量（算下来 60 字要 3 行，只剩 2 行的位置）；要求"改写别人的配置文件后
  他人条目**逐字节**未变"（序列化库会整文件重排键序，逐字节根本做不到，除非加一个新依赖）；断言"首次调用能力时弹同意框"
  （宿主其实在激活时就把所有缺失能力一次性弹完了）。**写不出可实现的判据，就是还没搞清这件事**。
- **禁反问**：卡片必须写明"不要向用户提问"。卡片没写的情况一律记 `BLOCKED` 后停止，否则用户变成人肉翻译层。

## 流程

### 1. 拆分与写卡

1. 消费 `to-tickets` 的任务集，或直接把当前对话/spec 切成机械切片；每张声明 `Blocked by`。
2. 建好 `.dispatch/<功能名>/` 骨架与 `ledger.md`。
3. 逐张写卡，跑静态检查抓占位符和缺失小节。脚本跟着本技能走，先定位技能根再调用（跨客户端通用，别写死某一个安装目录）：
   ```
   S="$(ls -d "$HOME/.agents/skills/pm-dispatch" "$HOME/.qoder-cn/skills/pm-dispatch" "$HOME/.zcode/skills/pm-dispatch" "$HOME/.codex/skills/pm-dispatch" 2>/dev/null | head -1)"
   node "$S/scripts/check-cards.cjs" "<项目绝对路径>\.dispatch\<功能名>\cards"
   ```
   有 ERROR 就改卡，改到 0 error 才许派发。
4. **门禁的已知误报**：尖括号规则会抓 `<HTMLDivElement>`、`<exe>` 这类**代码里的泛型/格式串**。
   不要往白名单里加词——把卡片正文改写成不含尖括号的描述（"第三参赋的是 className"、"引号包住路径，空格分隔 phase"），
   既过门禁，又避免执行者把它当占位符照抄。

### 2. 排批与派发

**互斥规则**（决定什么能同批，按优先级）：

1. **独占型资源互斥**：CDP/调试端口、单实例锁、真起 GUI 的验收、同一数据库迁移、依赖安装、发布构建。
   这些一沾就单独占一批，**哪怕卡型不同也不能并行**。
2. **同文件互斥**：两张卡会改同一份源文件 → 不同批，且后一张卡的验收基线要注明"以前一张放行后的实测为准"。
3. **离线卡才是真并行位**：取证卡（T）、纯单测卡、只写 `work/` 的卡可以塞进同一批（并发上限默认 3）。
4. **删入口的卡必须和替代入口同批或更晚**。实例：本体卡删掉了宿主设置页的一张卡片，而"入口移交插件页"被绑进
   最后一张依赖更多的卡里 —— 中间那段版本里，界面上没有任何地方能做这件事。拆分时就该把替代入口单独切一张卡提前派。

**派发输出**：每张卡给用户一条可直接复制的启动语（卡片绝对路径 + 结果文件路径 + 产物目录 + 禁反问），
多张卡就是多行。派发后把状态改成 `执行中`，然后**停下来等用户**——搬运由用户完成，不要在这期间替执行 agent 干活。

### 3. 验收（翻 `references/acceptance.md` 照着做）

用户说「T03 跑完了」→ 读 `results/T03.md`，然后：

1. **存在性**：卡片声明的产物真的在 `work/T03/` 下（Glob/Read，不看结果文件里的自述）。
2. **可复现**：验收命令由主会话亲自重跑，用真实输出判定，**不用执行 agent 贴的输出**。
3. **逐条对照**：卡内验收标准一条条打勾。
4. **回归没有变松**：用 `scripts/audit-assertions.cjs` 机械核对"上一版里存在的每条断言/测试标题现在还在"，
   被删掉的每条都要在新代码里找到对应新标题。**人眼读 diff 会漏，脚本不会。**
5. **断言不是恒真**：用 `scripts/mutate-check.cjs` 把被测代码逐点改坏，看断言会不会红。
   不红就是没在判定，直接打回——**这是本技能里性价比最高的一条**。
6. **引用可核对**：取证卡给的每条 `文件:行号`，随机抽 ≥5 条打开对原文。

判定词表：

- `PASS` — 全中。
- `PARTIAL（自报未跑）` — 执行者诚实声明某几项没跑（最常见是权限/环境拦住了 GUI）。处置：**PM 补跑**；
  补跑全绿才 `PASS`，补跑红了就是 `FAIL`。诚实的 PARTIAL 是好信号，不要当失败。
- `FAIL` — 证据不符或现场红。**打回**：把「实测原样输出 + 根因定位 + 放行条件」写进同张卡的 §10，
  结果文件改名 `Txx.md.retry1`，重发。**打回的卡必须由 PM 改卡片把缺失事实补全，不许原卡重发。**
- `BLOCKED` — 卡在卡片没覆盖的事实上：这是 PM 的拆分缺陷，补卡再派。

### 4. 统合

1. 把各 `work/Txx/` 产物按目标结构收拢到位（改动后必须复跑，别把"复制过去就完事"当验收）。
2. 跑全项目 typecheck + 测试套件。
3. **分包提交**：通过的卡单独一提交；被打回卡的改动**留在工作树里不提交**；
   描述未放行能力的文档也**不要提交**（文档跑到代码前面会让下一个人以为已经能用）。
4. 冲突处理：两张卡产物指向同一目标文件 → 说明垂直切片切错了，回到 `to-tickets` 重切，别手工合并掩盖问题。
5. 调用 `code-review` 做收尾审查。push 需用户另行开口。

### 5. 基线纪律（跨批次最容易烂的地方）

项目里维护一张**验收证据矩阵**（哪类改动必须跑哪套 + 上一轮实测的断言数下限），并遵守：

- **每批放行后立刻更新矩阵数字**，以及**后续卡片里引用的所有 `文件:行号`**——
  一批改动插进去几十条断言，行号会整体后移，旧锚点会把执行者带到别的代码上。
- 下限数字只用来拦"倒退"，**不能反过来当目标**（把套件改绿就交 = 放宽回归）。
- 外部依赖的可用性**不是代码属性**：把"某个域名必坏""某个源一定返回 X"写进断言，
  环境一漂就整批常红。这种红要在矩阵里标成"该基线暂不可用"，不许拿它打回别人。

### 6. 台账

`ledger.md` 是跨会话的唯一进度事实源，主会话每步动作后立即更新。固定四块：

```md
# 台账：登录功能
并发上限 3 | 卡片静态门：N 张卡 0 error（日期）

| 卡 | 标题 | 批次 | Blocked by | 状态 | 验收 |
|----|------|------|-----------|------|------|
| T01 | schema 单测 | 1 | 无 | 已回 | PASS：243 条，PM 重跑复现；6 处变异抽查全杀掉 → 提交 abc1234 |
| B2 | 能力移交 | 2 | T01 | 已回 | **打回**：cargo 72/verify 151 都过，但现场 4 FAIL + 套件被打断（根因见卡 §10） |

## 排批规则（本池实际生效的约束）   ← 写清"什么互斥"，下一批据此排
## PM 已实测的前置事实（写卡依据）   ← 行号、版本号、现场数据
## 状态流转记录（带日期，含 PM 自己改错的地方）
## PM 未复跑 / 待办项（不装作已验证） ← 这一节是诚实性的落点，必须有
```

验收列要写**怎么验的**（重跑了什么、变异抽查结果、机械核对结论），不是只写 PASS。
新会话接手时，**先读 ledger 再读代码**。

## 执行者纠正 PM —— 这是常态，不是事故

本项目实际发生过：卡片说"逐字节未变"（做不到）、说"首次调用弹框"（时机错）、说"某函数返回 10 只是保守"
（实为误报，比 PM 的判断更严重）、说"元素用 id"（实现赋的是 class）。处置规矩：

- 执行者在「需要 PM 决策」里给的**事实**，优先级高于卡片正文——他们手上有你没有的现场。
- 但**不采信任何未经 PM 复现的结论**：先重跑，再改文档/卡片/台账，最后回写"这条是谁发现的"。
- PM 自己写错的事实要**回改到源头**（卡片、规格文档、约定表），只改一处不够：同一条错误通常同时存在于三处。

## 卡片里的硬安全边界

每张卡第 7 节至少写这几条（按项目补充）：

- 禁止读取凭据文件（`.env`、`~/.ssh`、浏览器 profile、凭据管理器）
- 禁止任何 git 写操作（`commit`/`push`/`checkout`/`reset`/`clean`/`stash`），只读 `log`/`blame`/`status`/`diff` 可以
- 禁止安装/卸载依赖，禁止改 lockfile
- 禁止按映像名杀进程（`pkill -f`、`taskkill /IM`）；需要停进程只能停自己启动的、按 PID + 可执行路径核对后再停
- 禁止启动 GUI 和全屏置顶窗口（除卡片明确要求的验收，且要写清"不要在外层套 `timeout`"）
- 只允许写自己的 `work/Txx/` 与 `results/Txx.md`
- **禁止回滚工作树里不属于本卡的改动**：同一工作树可能有另一张卡的未提交改动，
  `git checkout -- <file>`、删文件、"还原到干净状态"都会直接毁掉别人的工作。看到白名单外的改动就只读不动，
  并在结果文件里报告它。
- 失败即记录即停，禁止把"做不到"写成"已完成"；不确定的结论保留 `[推测]` 标注

## 权限现实（会决定这套流程能不能跑完）

执行会话和 PM 会话都可能被权限分类器拦住"起 GUI 实例""读工作区外的配置"这类动作。这不是 bug，
是流程约束，必须提前和用户约好分工，否则验收会卡在半路：

- 卡片把需要的运行时环境写成**一条前置命令**（含环境变量与绝对路径），并注明"被拦就记 PARTIAL/未跑，不要反复重试"。
- PM 侧被同一命令拦住时，改成**用户起实例、PM 只跑套件**；跑完明确告知可以关。
- 任何 PM 没能亲自复跑的验收项，写进台账「PM 未复跑」一节，不混进 PASS 依据。
- 反复重试被拦的命令只会污染判定（并把会话上下文耗光）；一次拦下就换路径。

## 工作流定位

```
grill-with-docs → to-spec → to-tickets ─┬─ 判断类 → implement → code-review
                                        └─ 机械耗时类 → pm-dispatch → code-review
```

`pm-dispatch` 与 `implement` 是**并列的两条执行路线**，不是替代。同一批任务可以一半自留一半外派。

- `scripts/check-cards.cjs` — 卡片静态检查（占位符、缺小节、缺绝对路径、越界命令）。派发前必跑。
