# 项目经理派发（PM Dispatch）

主会话是**项目经理**：只做需求分析、拆分、写卡、调度、验收、统合。**不亲手做机械耗时的批量执行**——那部分写成任务卡，交给 flash 档模型在独立会话里并行跑，用户负责搬运。

判断留在主会话，执行外派出去。

## 分诊表：先决定这张卡给谁

| 特征 | 归属 |
|------|------|
| 产出能独立验证，不需要对话里的隐性共识 | 外派（写卡） |
| 批量、重复、逐条套用同一规则（补测试、加类型、迁移字段、逐个文件改写、跑数据收集） | 外派（写卡） |
| 需要全局推理、跨多文件权衡 | 主会话自留 |
| 定义验收标准、选接缝、敲定术语、架构决策 | 主会话自留（走 to-spec / domain-modeling） |
| 不可逆或影响共享状态（push、删数据、改 CI、装依赖、动 git） | 主会话自留，且需用户明确开口 |
| 一句话能改完的小改动 | 主会话自留，外派成本高于收益 |

**写卡前必问自己**：执行 agent 看不到这段对话，卡片里缺的事实他能自己补吗？补不了就必须写进卡片。

## 工作区布局

在项目根的 `.dispatch/<功能名>/` 下：

```
.dispatch/登录功能/
├── ledger.md            PM 台账，唯一进度事实源（只有主会话写）
├── cards/T01-schema.md   任务卡（只有主会话写，执行 agent 禁改）
├── results/T01.md        执行结果（只有对应执行 agent 写）
└── work/T01/             该卡的产物目录（该卡唯一可写区）
```

一卡一目录一结果文件 → **天然无写冲突**，这是能并行的前提。

## 任务卡解剖

用 `assets/card-template.md`。十节缺一不可：

1. **编号/标题/批次**
2. **背景** — 一句话说清为什么做这件事
3. **目标产出** — 具体到能被验证
4. **输入与事实** — 实测过的绝对路径、真实版本号、既有文件清单
5. **允许写入路径** — 白名单，只含 `work/Txx/` 与 `results/Txx.md`
6. **精确步骤** — 可直接粘贴的命令
7. **已知坑** — 从 `references/known-pitfalls.md` 挑相关的抄进去
8. **硬安全边界**
9. **自检与验收标准** — PM 判 PASS/FAIL 的客观条件
10. **回传契约** — 结果文件绝对路径 + 固定格式 + 禁止把"做不到"写成"已完成"

### 三条铁律

- **零占位符**：交付出去的卡片里不许残留尖括号槽位、双花括号槽位、`TODO`。弱模型会原样照抄。示例值必须写成"以 T06 为例，换成你自己的任务号"。
- **命令实测**：卡片里的命令，主会话先自己跑通一遍再下发。公共脚手架（超时包装器、日志格式、目录约定）由主会话先建好验证，不留给 N 个 agent 各自发明。
- **禁反问**：卡片必须写明"不要向用户提问"。卡片没覆盖的情况一律记 `BLOCKED` 后停止，否则用户变成人肉翻译层。

## 流程

### 1. 拆分与写卡

1. 消费 `to-tickets` 的任务集，或直接把当前对话/spec 切成机械切片；每张声明 `Blocked by`。
2. 建好 `.dispatch/<功能名>/` 骨架与 `ledger.md`。
3. 逐张写卡，跑静态检查抓占位符和缺失小节（Qoder 的 Bash 工具里 `$HOME` 会展开成本机用户目录，无需改成绝对路径）：
   ```
   node "$HOME/.qoder-cn/skills/pm-dispatch/scripts/check-cards.cjs" "<项目绝对路径>\.dispatch\<功能名>\cards"
   ```
   有 ERROR 就改卡，改到 0 error 才许派发。

### 2. 派发

按批次取前沿（阻塞者全部 PASS 的卡），每张卡给用户一条可直接复制的启动语：

```
读取并严格执行 D:\proj\.dispatch\登录功能\cards\T03-注册接口.md
你的结果只能写入 D:\proj\.dispatch\登录功能\results\T03.md
产物只能写入 D:\proj\.dispatch\登录功能\work\T03\
不要问我问题。卡片没写的情况一律在结果文件里记 BLOCKED 后停止。
```

**并发上限**：默认同一批 ≤3。触碰同一份依赖安装、同一数据库、或要启 GUI 的卡不许同批并发——它们会互相踩。批次号和上限写进 ledger。

派发后把状态改成 `执行中`，然后**停下来等用户**——搬运由用户完成，不要在这期间替执行 agent 干活。

### 3. 验收

用户说「T03 跑完了」→ 读 `results/T03.md`，三查：

1. **存在性**：卡片声明的产物文件真的在 `work/T03/` 下（Glob/Read，不看结果文件里的自述）。
2. **可复现**：验收命令由主会话亲自重跑一遍，用真实输出判定，不用执行 agent 贴的输出。
3. **逐条对照**：卡内验收标准一条条打勾。

判定：

- `PASS` — 全中。
- `PARTIAL` — 主用途达成但有缺口：主会话自己补齐缺口（补齐属于判断活），不再外派。
- `FAIL` — 证据不符。**打回**：在同一张卡的"上一轮失败原因"节写清具体证据（文件路径+行号+实际输出），结果文件改名 `T03.md.retry1`，重发。打回的卡必须由主会话改卡片把缺失事实补全，不许原卡重发。
- `BLOCKED` — 执行 agent 卡在卡片没覆盖的事实上：这是 PM 的拆分缺陷，补卡再派。

### 4. 统合

全部批次 `PASS` 后，主会话自己做（不再外派）：

1. 把各 `work/Txx/` 产物按目标结构收拢到位。
2. 跑全项目 typecheck + 测试套件。
3. 冲突处理：两张卡的产物指向同一目标文件 → 说明拆分时垂直切片切错了，回到 `to-tickets` 重切，别手工合并掩盖问题。
4. 调用 `code-review` 做收尾审查。
5. 项目有 `.git` 时按用户既有习惯提交；push 需用户另行开口。

### 5. 台账

`ledger.md` 是跨会话的唯一进度事实源，主会话每步动作后立即更新：

```md
# 台账：登录功能
并发上限 3 | 脚手架已验证 2026-10-12

| 卡 | 标题 | 批次 | Blocked by | 状态 | 验收 |
|----|------|------|-----------|------|------|
| T01 | schema | 1 | 无 | PASS | 2026-10-12 重跑迁移通过 |
| T03 | 注册接口 | 1 | T01 | 执行中 | — |
| T05 | 登录 UI | 2 | T03 | 待派 | — |
```

新会话接手这套流程时，**先读 ledger 再读代码**。

## 卡片里的硬安全边界

每张卡第 8 节至少写这几条（按项目补充）：

- 禁止读取凭据文件（`.env`、`~/.ssh`、浏览器 profile、钥匙串）
- 禁止任何 git 写操作（`commit`/`push`/`checkout`/`reset`/`clean`/`stash`），只读 `log`/`blame`/`status` 可以
- 禁止安装/卸载依赖，禁止改 lockfile
- 禁止按映像名杀进程（`pkill -f`、`taskkill /IM`）；需要停进程只能停自己启动的、按 PID + 可执行路径精确杀
- 禁止启动 GUI 和全屏置顶窗口
- 只允许写自己的 `work/Txx/` 与 `results/Txx.md`
- 失败即记录即停，禁止把"做不到"写成"已完成"；不确定的结论保留 `[推测]` 标注

## 工作流定位

```
grill-with-docs → to-spec → to-tickets ─┬─ 判断类 → implement → code-review
                                        └─ 机械耗时类 → pm-dispatch → code-review
```

`pm-dispatch` 与 `implement` 是**并列的两条执行路线**，不是替代。同一批任务可以一半自留一半外派。

## Resources

- `scripts/check-cards.cjs` — 卡片静态检查（占位符、缺小节、缺绝对路径、危险命令）。派发前必跑。
- `assets/card-template.md` — 十节任务卡模板，含回传契约格式。
- `references/known-pitfalls.md` — 本机实测踩坑库，写卡第 7 节时按条挑用。
